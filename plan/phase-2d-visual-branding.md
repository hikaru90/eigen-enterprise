# Phase 2d — Visual branding (taste elicitation, extraction, selection, apply, editor)

**Status:** APPROVED for implementation (owner directive 2026-09-09; design reached by grilling session, every branch of the design tree visited)
**Supersedes:** phase-2c **D1** (visual pipeline is now **v0 scope**, not out-of-scope)
**Parallel to:** phase-2c M3–M5 (voice/content pipeline) — unchanged, orthogonal
**Module:** `brand` (visual features live inside the existing branding module; tool namespace `brand.*`)

## Concept

Spotify-onboarding-shaped taste elicitation over a **curated corpus of formalized designs**: the owner selects style cards, selections narrow the space, one design wins and is **applied to all user-facing surfaces**; a native browser editor (flexbox/web tech — no Penpot, no second database, ever) then fine-tunes it. Zero LLM at selection/editor/publish runtime — intelligence is baked into the corpus (formalization, similarity, clustering) at build time and into the extraction judge loop. A **URL → design-system extraction pipeline judged by the owner** is the first-priority corpus growth engine.

## Milestones

- **M1 — Canonical format**: seeds schema + `expand()` (pure, pinned libs) + snapshot tests (`expand(seed) === tokens.json`) + Style Dictionary build → CSS-var emitter; corpus item type + validation; corpus JSON shape (style + resolved tokens + vector + cluster id).
- **M2 — Extraction pipeline + judge loop (first priority)**: SSRF-guarded fetch → computed-style + screenshot capture → 3 candidates per round through the gateway → minimal specimen renderer + judge UI (closest / correct / reject; corrections = token-level edits) → accepted item staged for corpus; judged-pairs table (next sequential migration idx per journal rules); OFL font mapping table.
- **M3 — Corpus assembly**: Tier-1 ingest (theme CSS vars → corpus items, human-validated) + hand-authored archetypes; build script: vectors, k-NN, clusters (HDBSCAN/k-means) → corpus JSON; build-time LLM cluster naming.
- **M4 — Selection wizard**: standalone route (journey engine is chat-shaped — poor fit; artifact/approval mechanism not needed here). `brand_visual_sets` migration + store (draft/active/retired, one-active, draft-only writes) + `brand.tokens_list` + draft-write tools. Cluster grid → seeds → centroid → top-3 shortlist → working draft. Simple grid only (V7).
- **M5 — Publish/apply**: `brand.visual_set_activate` approval-gated; global `:root` CSS-var emission from active set; `/s/[slug]` + app shell + shader consumption (shader tints from tokens, grayscale while inactive).
- **M6 — Editor**: full specimen canvas + token panel + click-to-highlight token drivers (extends the M2 renderer); edits write draft via kernel tools.
- **M7 — Tree navigation (last priority)**: k-NN descent, tunnel links to adjacent clusters, breadcrumbs (Every Noise pattern).

## Workstream layout

Single stream `wt/brand-visual`. M1–M3 touch `modules/brand/` (format, extraction, corpus) + new migrations — disjoint from phase-2c M3/M4 (`src/lib/server/llm/**`). Coordination point: M5 touches website routes (`/s/[slug]`) — keep the diff surface minimal; route reads brand store directly (same idiom as existing direct website-store read). Corpus build scripts are dev-time, committed output only (the `ee` CLI vite-8 regression must not block — scripts run via vitest/node directly until fixed).

## Guardrails binding this phase

- All LLM calls through the gateway (`src/lib/server/llm/`) — extraction and cluster naming included; cost + principal attached. No direct provider calls.
- No regex/keyword heuristics for semantic anything — deterministic layer is pure math over token vectors; LLM only where semantic (extraction, cluster naming); post-LLM code parses/validates/persists.
- Kernel discipline: every mutation a `brand.*` tool (human-only guards per 2c D5); `visual_set_activate` approval-gated; draft-only writes, active immutable (G23); every mutation → audit event, vcs auto-commit.
- Fail loud: no fallback styles, no `||` defaults; absence of active visual set = app's own style (an explicit in-repo artifact, not a fallback path).
- Migrations: both SQL file + journal entry, sequential idx.
- Fonts: OFL only, shippable files only; license check is part of corpus acceptance.
- Tests first: snapshot tests for `expand()`, vector/distance math, store guards; extraction judge loop covered by deterministic seams (fetch/capture/LLM mocked at the seams).
